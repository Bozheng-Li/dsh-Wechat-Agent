# 菜单归并与自然状态维护记录

2026-11-07，北京时间。本轮为未发布的本地维护更新，基础版本仍为 `0.2.0-preview.6`，未发布 npm 或推送 Git。

## 操作入口与数据

- 发送恢复位于“处理记录 → 发送恢复”，侧栏保留处理记录入口。原诊断页跳转继续进入正确的二级页面。
- 记忆维护位于“记忆库 → 记忆维护”，与会话记忆窗口、全局长期记忆和图片记忆组成四个标签。全局长期记忆编辑和事实维护共用原有 `global-memory.md`，切换保留编辑草稿。
- 恢复项、恢复历史和长期事实支持单条删除及分类整理。恢复清理覆盖完整分类或全部历史，超过显示上限的条目也按确认范围处理。
- 删除确认保留原范围和文件版本，刷新不会扩大范围；保存失败保留列表、确认目标和有效期编辑草稿。正在生成、发送或等待回执的恢复项不能删除。
- 恢复清理保留原聊天归档、真实微信回执和防重发依据。事实删除保留修改前备份与旧来源删除标记；删除旧冲突事实不会自动采用新候选。

## 自然陪聊的职责

参与性格决定有机会时是否开口及如何表达。条数提供新讨论中的接话机会，分钟间隔提供定时开话题机会；两者共用一次模型判断、发送队列和主动冷却，同时到达条件时合并。达到间隔只安排判断，有合适内容才发送。

修改参与性格、条数或其他无关设置保留既有时间、无人回应计数、冷却和发送待核对状态。改变有效分钟间隔才重新安排时间。受阻的条数检查及无关后续不继续推迟定时机会；无关后续也不增加冷场退让。

发送结果不明或部分确认后，主动参与持续暂停。管理员先在微信和处理记录核对，再展开“核对发送结果后恢复”、勾选确认并恢复。恢复只安排新的机会，不重发旧消息、不改写真实回执；保存失败仍保留暂停状态。

昵称、@、`/agent` 的优先唤醒，以及固定或随机 1–100 条数量设置继续保留。
