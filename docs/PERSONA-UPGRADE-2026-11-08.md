# 人设提示词升级与验收 · 2026-11-08

本轮基于已发布的 `0.2.0-preview.8`，属于新的源码更新。先前版本的安装、公开发布和失败实验不被本轮结果覆盖。

## 修改范围

- 18 套模板保留 ID、名字及分类，重新明确价值取向、日常关注点、求助反应与情绪变化。示例区分闲聊和明确求助，修正擅自补经历、归因或安排的内容。
- 提示块继续声明使用原则，精简重复限制。当前会话人设整套优先；未独立设置时才使用默认人设。事实、当前目的、身份真实性与输出协议各有职责。
- 旧内置正文原来只是保存副本，模板变更不会随之生效。本次在首次启动时以完整正文 SHA-256 识别 preview.8 的 18 套模板，先备份原状态再升级；支持结构化字段和实际编辑器保存的单段正文。名字、别名、独立会话选择和其他配置保留。任意正文改写都不匹配，后续主动回退也不再自动改写。
- 编辑页增加编写与示例指引，说明名字同时用于自称和唤醒。

## 验收标准（模型实验前确定）

1. 事实：数字、单位、人物、物品去留与先后状态保留；不能增补地点、天气、经历或心理动机。
2. 目的：闲聊不顺手给建议；同一发言者的明确偏好延续，后续求助、计算或创作能切换。
3. 角色：日常、认真和多轮回应有相应态度与语气，不能只靠固定口癖；允许不同角色在普通问候上相似。
4. 身份与格式：配置完整名字生效；自定义原文保留；管理员固定约定、真实身份与 JSON 协议不退化。
5. 链路：使用实际 `configDraft → configPayload → validatePersona` 保存格式，截获最终原生模型请求，验证只有当前角色、没有额外宿主系统文字；恢复会话与工具后的正文延续角色。

自动断言检查传参、格式和明确事实；角色自然度、未明说的建议和事实增补须逐条人工审阅。自动断言全过不能代替语义验收。

## 模型实验设计

- 基线使用 preview.8 发布时的不可变源码与 testing bundle 快照；候选使用单独冻结的源码及 bundle，记录哈希。
- 每批读取运行中 `haina / deepseek-v4.1-flash` 及实际推理强度、温度和输出上限，不更换模型来代替当前效果。
- 先做交替顺序的新旧配对：旧组合与旧模板对新组合与新模板；另列同一实际保存正文下的组合对照和自定义正文，避免测试仍误用旧模板。
- 再用未放入模板的场景检查 18 角色，并覆盖多轮、按需记忆、只聊转求助、固定约定及留出场景。
- 保留所有回答和失败，不以不断重试筛选“好答案”。可修改候选，但每次另冻结、另记录，不能覆盖前一轮证据。
- 所有消息都是隔离的合成模型请求，不经过微信发送通道。生产账号、授权、模型参数及备注在前后核对。

人工审阅确认的有效项：

- 最终原生请求包含实际编辑保存格式中的完整人设，只有一个当前角色块；当前问题完整保留，恢复会话不混入未经筛选的原生旧问答。默认与会话独立人设仍整套二选一。

- 实际记忆工具在两个角色下都使用最新更正的地点，没有串入另一人的目的地；但请求“回答那一个地方”后仍附加解释，简洁度并未完全达标。
- 多轮闲聊转计算得到正确的 `3/8`；留出问题能输出完整新名字、四行诗和新的求助内容。安静陪伴与十二分钟等车的先后关系在留出样本中正确保留。
- 问候没有再根据服务器时间纠正对方。角色仍可能加过多修辞，因此这项只证明时间输入干扰被移除。

这些结果证明具体输入、保存与组合链路已可验证，不能证明当前模型会稳定遵守所有规则，也不足以断言更强提示或其他模型一定无效。未将候选发布为“全部修复”的正式版本。
