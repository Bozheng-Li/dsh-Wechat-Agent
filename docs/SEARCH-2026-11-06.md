# 联网搜索接入与验证 · 2026-11-06

本次故障中，DSH 搜索请求实际到达 DeepSeek 官方接口并返回 HTTP 401。聊天使用另一条模型服务，聊天可用不能证明搜索凭据有效；原插件把具体错误统一改成“搜索未完成”，导致回复误把认证问题描述为网络未连接。

新版保留可操作的错误分类，并在模型设置显示最近一次实际搜索的结果。查询没有来源时明确说明没有可引用结果，不将模型记忆冒充刚搜索到的论文。

## 两种可选服务

- Tavily：新安装默认选择此服务，搜索总开关初始关闭。支持官方 HTTP API 与 Tavily Hikari 代理，接口地址和服务选择保存在插件配置，密钥单独保存到 DSH 凭据服务。
- DeepSeek 原生：复用 DSH `0.2.1-rc.5` 已注册的原生搜索实现，以独立密钥请求官方搜索接口，保留结构化来源。宿主的搜索选择、聊天服务和其他凭据保持原样。

切换只影响之后开始的搜索；已开始的回复保留接收时的服务和地址。不会因某条链路失败而自动把查询发送到另一服务。搜索工具只接收有限长度的公开查询，不提交完整微信聊天、记忆或图片。

## 实际验证

在本机 DSH 所有者上下文分别执行 `site:arxiv.org LIRA`：

- DeepSeek 原生搜索成功，返回 5 条来源，耗时约 4.6 秒。
- Tavily Hikari 搜索成功，返回 5 条 arXiv 来源，耗时约 3.4 秒。

用户提供的 Tavily 服务公开文档规定 HTTP API 基址为 `https://tavily.fuhuagoogle.top/api/tavily`。入口首页直接拼 `/search` 返回 404，改用文档规定的 `/api/tavily/search` 后查询成功。本机按用户要求默认使用该 Tavily 服务，保留 DeepSeek 原生选项。

两种密钥均通过 DSH 凭据服务保存并核对读取结果。报告仅记录配置是否成功、公开来源、错误分类及耗时；测试没有发送真实微信消息，也没有发送维护通知。

回归覆盖独立凭据、实际选中服务、配置快照、无静默回退、认证与限流错误、响应大小上限、取消、空结果、所有者权限及密钥保存时仍在运行的回复。

## 运行实例的配置恢复

两条接口验证通过后，本机回复仍出现“上不了网”。读取正在运行的实例发现：搜索总开关尚未开启，Tavily 地址仍为官方默认值。配置现已应用到实际回复流程，并使用当前 DSH 聊天模型完成带有旧失败上下文的真实搜索验证；模型实际调用 Tavily，取得 5 条来源并返回 arXiv 链接。

本机随后安装了经过完整公开下载校验的正式 `0.2.0-preview.3` 包，原生界面再次确认默认启用公益 Tavily，DeepSeek 密钥保留并可切换。详见[本机正式版升级记录](LOCAL-RELEASE-PREVIEW-3-2026-11-06.md)。
