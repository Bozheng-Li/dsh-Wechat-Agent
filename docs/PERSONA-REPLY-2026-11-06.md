# 人设与自然回复修复 · 2026-11-06

本轮为源码修复和本地构建，未执行 npm 发布或运行插件安装。

## 触发与原因

用户要求创作时，回复已有几首诗，却继续赠送签名并以“想往哪个方向写”引导下一轮服务。旧检查只识别少量客服词和 Markdown 格式，此段未触发改写。

旧全局自然规则写明“优先于人设里的格式习惯”，既嵌入默认 `AGENT.md`，又在完整系统提示词末尾重复注入。规则提供统一的朋友口吻示例，削弱了当前角色的表达差异。二次改写另有配置丢失：未传账号补充要求，重新读取模型和全局设置，可能改变同一轮任务的口吻或参数。

本机保存的目标会话使用独立“墨白”模板，模板明确以通顺白话为底、少量轻古风。默认人设不会叠加到独立会话人设；所核对的全局身份仍为默认正文，账号补充回复要求为空。诗中旧书、灯、热汤等意象与模板吻合，说明角色内容确实传入。

## 修复

- 全局规则先提供默认表达习惯，再叠加当前人设和账号要求；角色的词汇、节奏、态度、自称与互动方式落实到正文，创作保留必要篇幅和格式。
- 默认全局身份保留事实、记忆和执行边界，移除重复自然规则。只按已知完整内容哈希迁移未编辑的旧默认文件；自定义正文和无效文件均不改写。
- 检查已完成作品之外的服务式菜单和额外签名；保留必要追问、明确要求的选项、签名、客服文案、引用和代码。
- 无工具改写沿用同一轮的全局身份、人设、账号要求、模型路由、温度和输出上限。改写不能重新执行任务，符合请求的作品按原文保留；仍有机械收尾时记录失败。
- 人设页说明、README 与包内 `CHANGELOG.md` 同步更新。父项目日志链接同一份插件日志。
