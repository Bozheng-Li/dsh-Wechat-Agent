# 插件装配与生命周期

[返回总架构](01-总架构.md)

## 职责与入口

`backend/index.mjs` 导出 `inject`、`apply`、`createPluginService` 和 `rpcHandler`；构建后对应 `lib/index.js`。`backend/app/plugin.mjs` 是 DSH 服务端插件的装配入口，声明所需宿主服务（连接、Web、Agent、模型、会话持久化、工作区、附件和凭据），管理唯一实例、目录锁、生命周期和 RPC 注册。`cordis.patch.yml` 将插件加入 Cordis 组件树。

## 初始化顺序

1. `apply(ctx)` 从 `DSH_HOME` 或用户目录下的 `.dsh` 确定 bootstrap：`wechat-agent/`。`resourcePath()` 则定位已安装的**包资源**，不等于用户工作目录。
2. `acquireLock(bootstrap)` 防止多实例并发使用同一份工作数据；`readWorkspaceLocation` 解析实际数据根目录。
3. `new WechatRuntime(...)` 组装根绑定对象：`StateStore`（配置/会话状态）、`AgentIdentity`、`DshAgentRunner`、`WorkerClient`（微信子进程）、`WechatChannel`（业务聚合）以及 `TaskScheduler`。子进程状态和消息通过事件转入 `channel`。
4. `runtime.ready()` 等待 Worker 就绪，登记聊天和工作的 Agent 工作区，准备工作项目并刷新搜索、生图凭据；`activate()` 按 `connectionWanted` 恢复连接，启动提醒、朋友圈及自然陪聊调度。
5. `createPluginService` 创建服务后，`ctx.connection.register(ctx, CHANNEL, rpcHandler(...))` 注册 `/wechat-agent`。启动失败时保留公开错误供状态页查看，不将旧授权静默重置。

## 关闭与目录切换

`ctx.effect` 的 disposer 负责完整关闭顺序：`lifetime.abort()` 阻止新操作，等待各 runtime 关闭和服务操作排空，最后释放 bootstrap 锁。`WechatRuntime.stop()` 关闭定时器、会话队列、工作任务和朋友圈，再等待 Worker 退出；`close()` 额外释放当前目录锁。

修改全局工作目录时，`relocateWorkspace` 停止旧 runtime，迁移数据，创建新 runtime，提交目录指针，替换 `service` 引用，再激活新实例。任何失败都尽量回滚迁移并恢复旧实例；若恢复也失败，返回明确错误并保留两端数据。不要仅修改 `runtime.root`：存储、Worker、缓存和调度器都绑定根目录。

## 维护边界与验证

- 新的根绑定服务应在 `backend/app/runtime.mjs` 构造和关闭，页面操作接入 `backend/app/service.mjs`，不要由功能模块反向引用装配层。
- 目录迁移与锁须保持“停止旧实例 → 创建新实例 → 原子提交”的顺序；失败不清理用户数据。
- 重点测试：`tests/runtime-workspace.test.mjs`、`tests/workspace-root.test.mjs`、`tests/plugin-service.test.mjs`；构建执行 `npm run build`。
