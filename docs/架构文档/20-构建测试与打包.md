# 构建、测试与打包

[返回总架构](01-总架构.md)

## 构建管线

`package.json` 声明 DSH 插件元数据、Windows x64/DSH 最低版本、服务端与浏览器包入口。`scripts/build-dsh-plugin.mjs` 使用 rolldown 从 `backend/index.mjs` 生成 `lib/index.js`，从 `backend/worker.mjs` 生成 `lib/worker.cjs`，从 `frontend/index.jsx` 生成 `lib/client.js`；`tests/exports.mjs` 还会生成只用于本地测试的 `lib/testing.js`，不会进入正式发布包。表情原图是账号运行数据，不随插件打包，包审计拒绝旧版网上内置图片。

`package.json.files` 是发布资源白名单：运行文件、默认配置、包内提示词、许可证和所需 runtime 必须显式列入；运行中生成的 `storage/`、源码 `tests/`、临时文件、账号配置和密钥不得进入包。`scripts/package-resources.mjs` 和 `audit-dsh-package.mjs` 校验复制/审计结果。

## 常用命令

```powershell
npm ci
npm run build
npm test
npm run test:structure
npm run test:ui
npm run test:visual
npm run test:python
```

`npm test` 会先构建再执行 Node 回归；`test:structure` 专项检查源码依赖方向、循环、浏览器边界及资源路径。原生 DSH 集成的隔离命令有 `test:work-native`、`test:work-parallel-native`、`test:work-tools-native` 和 `test:remote-native`，需可用的 DSH SDK 路径，使用合成账号，不必登录真实微信。Python 侧由 `tests/native_engine_test.py` 覆盖运行时边界。CI 在 `.github/workflows/ci.yml` 使用 Windows、Node 22、Python 3.13 运行相关检查。

## 完整插件包

`npm run engine:prepare -- <微信组件目录>` 核验本地微信 3.9 x64 组件，`npm run pack:plugin` 补齐 Python 嵌入环境和 runtime 并输出 `release/*.tgz` 与摘要，`npm run audit:package` 复核成员与哈希。微信专有二进制与真实会话凭据不存入 Git。源码包在 `package.json` 中仍设 `private: true`，应由受控脚本生成发布包，不能用直接 `npm pack` 代替完整打包。

## 测试选择

纯文档修改可核对 Markdown 相对链接和源码路径，无需触发长时间构建；代码修改按受影响模块选专项测试，再跑 `npm test`。改提示资源、发布清单或构建入口时，必须补做 `tests/package-resources.test.mjs` 和包审计。详细开发与发布步骤见 [开发说明](../DEVELOPMENT.md)。
