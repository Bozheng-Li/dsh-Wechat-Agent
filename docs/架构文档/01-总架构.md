# 总架构

> 本文是 `dsh-Wechat-Agent` 的总架构说明与文档索引。各模块的细节分别位于同目录下的独立文档，本文只保留"整体如何拼起来"所需的全局视图。
>
> 适用版本：`0.2.0-preview.8`（Windows x64 · DeepSeek-Harness `0.2.1-rc.5` · Node.js ≥ 22.18）。

## 一、项目定位

`dsh-Wechat-Agent` 是一个 **DeepSeek-Harness（DSH）插件**，把 DSH 的模型能力、拟人化对话、持久记忆、定时提醒、朋友圈运营和原生工作（编程/文件/命令）带到微信会话中。

它的本质是一个"宿主内嵌的可控自动化系统"：

- **运行在 DSH 宿主进程内**：通过 Cordis 插件模型注入宿主服务（Connection、WebServer、Agents、LLM、Tools、SystemPrompt、Attachments、Credentials 等）。
- **自带一个微信协议子进程**：通过 IPC 与宿主通信，不依赖桌面版微信窗口。
- **唯一的对外入口是页面 RPC**：所有管理操作都由前端页面发起，经 `/wechat-agent` 通道进入后端。
- **所有业务配置落在工作目录的 `config.yaml`**，运行状态、记忆、任务、素材分目录持久化。

一句话概括数据流：

```text
微信服务端 ⇄ 协议子进程(worker) ⇄ IPC ⇄ 宿主插件(backend/app) ⇄ 功能模块(modules) ⇄ DSH Agent
                                                     ⇅
                                       浏览器页面(frontend) ── RPC ──┘
```

## 三、分层结构

项目按**依赖方向**严格分层（由 `tests/source-structure.test.mjs` 守护）：

| 层 | 目录 | 职责 | 允许依赖 |
| --- | --- | --- | --- |
| 浏览器层 | `frontend/` | React 页面、样式、RPC 客户端 | 浏览器组件、`shared/`、人设数据 |
| 入口与装配层 | `backend/app/`、`backend/rpc/` | 插件生命周期、RPC 分发、服务编排 | 所有模块 |
| 平台支持层 | `backend/config/`、`backend/storage/`、`backend/platform/` | 配置事务、原子写入、路径解析 | `shared/` |
| 通信层 | `backend/wechat/` | Worker 进程、IPC、微信协议、朋友圈协议 | `shared/` |
| 功能层 | `modules/` | 各业务能力（对话、记忆、工作、朋友圈等） | `shared/`、`backend/storage`、`backend/config` |
| 契约层 | `shared/` | 前后端共用的纯函数与数据契约 | 无实例 |
| 提示层 | `prompts/` | 全部模型提示、工具说明、人设 | 无业务逻辑 |
| 构建与测试 | `scripts/`、`tests/` | 打包、回归、隔离验证 | — |
| 运行资源 | `runtime/`、`assets/` | Python、微信组件、内置表情 | — |

关键约束：

1. **模块不反向导入装配层、RPC 或页面**。
2. **`backend/storage` 与 `backend/config` 不依赖微信协议或功能实例**。
3. **`shared/` 保持无实例、纯函数**，可在浏览器与服务端同时执行。
4. **构建产物只有 `lib/index.js`、`lib/client.js`、`lib/worker.cjs`**，由 `scripts/build-dsh-plugin.mjs` 用 rolldown 生成。

## 四、运行时生命周期

```text
DSH 加载插件
  → apply(ctx)
      1. 解析 DSH_HOME，得到 bootstrap 目录 ~/.dsh/wechat-agent
      2. acquireLock(bootstrap)                     独占锁，防止多实例
      3. readWorkspaceLocation(bootstrap)           读取实际工作目录
      4. new WechatRuntime(...)  →  ready()
           StateStore / AgentIdentity / DshAgentRunner
           WorkerClient（spawn lib/worker.cjs）
           注册 agent 工作区、加载搜索与生图凭据
      5. runtime.activate()                         连接微信、启动调度器
      6. createPluginService(...)                   创建 RPC 服务
      7. ctx.connection.register(ctx, '/wechat-agent', rpcHandler)
  → 用户操作 / 微信消息 / 定时器驱动全部业务
  → 插件卸载
      ctx.effect(() => close) → 关闭 runtime → drain 服务 → 释放锁
```

**工作目录迁移**（`relocateWorkspace`）是一个事务：停旧 runtime → 迁移文件 → 打开新 runtime → 提交指针 → 释放旧锁；任一步失败都会回滚并尽量恢复原 runtime。

## 五、三条主数据通道

### 1. 消息通道（面向微信）

```text
微信服务端 → WorkerClient('message') → WechatChannel.receive
   → incoming.mjs（去重、授权、模式判定、唤醒词解析）
   → queue（直接回复 / 主动参与 / 工作请求 / 远程查询）
   → reply.mjs（记忆装载 → 工具注册 → runner.run → 发送）
   → transport.send → 服务端回执 → store.update(state='sent')
```

核心保证：

- **不重发**：没有拿到服务端回执的发送一律记为 `unknown`，不自动重放。
- **回复前复核**：发送前重新检查授权、账号、配置版本、自然陪聊状态。
- **单一在途**：普通回复同一时刻只有一条在生成；工作回复按会话分道。

### 2. RPC 通道（面向页面）

```text
frontend → connection.call('/wechat-agent', endpoint, payload)
   → rpcHandler：校验 principal.kind === 'owner'，白名单 endpoint
   → service.call：状态查询直接返回；其余进入 mutate 串行队列
   → modules/<功能>/actions.mjs 或 service 内分支
```

### 3. 模型通道（面向 DSH Agent）

```text
modules/agent/runner.mjs  → ctx.agents.create / resume
   → setup(ctx, agent)：注册系统提示、工具、请求参数钩子
   → agent.followup({ role: 'user', content })
   → agent.whenIdle() → 提取最终正文
   → polishReply / reviewMemoryReply → 交给 reply.mjs 发送
```

## 七、关键设计原则

| 原则 | 体现 |
| --- | --- |
| **先提交意图，后跨越副作用边界** | 发送前写入 `state='sending'`、`sendAttempted=true`；崩在中途就是 `unknown`，永不自动重发 |
| **回执优先** | 只有拿到 `delivery === 'server-ack'` 且 messageIds 合法才算成功；部分确认记 `partial` |
| **授权在每次读写前后复核** | `assertAllowed` 在入队、生成、发送、工具执行前后都会重新检查账号/授权/配置版本 |
| **配置与状态分离** | `config.yaml` 只管业务设置；`storage/state/channel.json` 只管运行索引；每个会话 `conversation.json` 是独立原子快照 |
| **多文件写入走事务** | `backend/config/transaction.mjs` 写 journal，启动时先恢复中断事务 |
| **工作与聊天隔离** | 工作会话保留 DSH 原生预设与工具，不注入微信聊天历史/人设；聊天会话不继承桌面预设 |
| **生图参数受配置约束** | 生图提供方、模型和尺寸由工具调用在已配置目录内选择；未指定时使用配置默认值，密钥由凭据服务保管 |
| **提示词外置** | 所有提示在 `prompts/` 中，通过 `promptText`/`readPrompt` 读取并校验，打包按 `package.json.files` 白名单复制 |

## 十、术语表

| 术语 | 含义 |
| --- | --- |
| **Runtime** | `WechatRuntime`，一组与工作目录绑定的服务集合，目录迁移时整体替换 |
| **Channel** | `WechatChannel`，消息队列、回复流水线与各业务服务的聚合点 |
| **Reply / Record** | 单条待处理消息的处理单元 / 持久化记录，`record.key` 是幂等键 |
| **contextKey** | DSH 会话归属键，决定同一会话复用哪条 Agent 会话 |
| **Selector / Scope** | `{ accountId, chatType, peerId[, senderId] }`，几乎所有操作的授权单位 |
| **Worker** | 独立的微信协议子进程（`lib/worker.cjs`），由 `WorkerClient` 用 `spawn` 建立 IPC |
| **Server ack** | 微信服务端返回的消息 ID 数组，发送成功的唯一判据 |
| **Tool** | 暴露给模型的函数，分聊天工具与原生工作工具两类 |
| **实例锁** | 由 `backend/storage/locks.mjs` 管理的工作目录独占锁，防止多个宿主实例同时驱动同一份微信数据 |
