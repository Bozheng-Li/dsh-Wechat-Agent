# 配置与存储

[返回总架构](01-总架构.md)

## 两种数据各有归属

安装包根部 `config.yaml` 仅是**默认模板**。实际业务设置保存在工作目录的 `config.yaml`，包括账号授权、连接意愿、模型选择、统一人设、会话模式、存储路径、记忆与素材参数、工作并发、管理员和生图目录。`backend/config/repository.mjs` 用 YAML 文档解析器严格校验字段、版本和 `ownerStoreId`；路径引用的自定义提示词只接受工作目录 `prompts/*.md` 内普通文件。

`backend/storage/state-store.mjs` 将运行状态拆为 `storage/state/channel.json`（全局索引）与每个会话的 `conversation.json`（已见消息、回复记录、会话 ID、计数和自然陪聊状态）。`initialize.mjs` 先恢复未完成配置事务，再载入 YAML 与所有会话快照，校验归属并迁移旧格式。`StateStore.remember` 在持久写入去重声明后才将消息追加到记忆；`update` 在得到已确认发送记录后追加助手回复。聊天历史本身不会因记忆压缩而被改写。

## 配置写入协议

`ConfigurationRepository.assertCurrent()` 比对 YAML 和已引用提示词的签名，拒绝覆盖用户外部编辑；设置修改调用 `commit`，将 Markdown 内容先发布，再由 `backend/config/transaction.mjs` 维护多文件事务记录。启动时 `recoverConfigurationTransaction` 处理提交中断。`backend/storage/atomic-text.mjs`、`atomic-json.ts` 提供原子写入；`locks.mjs` 防止并发实例或会话目录冲突。无效文件/归属不符时失败并保留原始数据，不自动重置账号授权。

## 状态恢复规则

- 启动前对旧状态生成备份，`v1` 会话索引迁移为独立快照；每条记录的幂等键由账号、会话、服务端消息 ID 组合。
- 断点时仍在 `sending` 的记录标记为 `unknown`，其余在途记录取消，绝不因重启直接重发。
- `role-cards.mjs` 保存会话角色卡并进行 revision 校验；记忆、任务、素材及工作各自有独立目录和校验，不混写进主索引。
- `backend/storage/workspace.mjs` 处理目录定位、路径检查与整目录迁移；不要把包资源目录当作用户数据目录。

## 维护与验证

新配置字段需同步默认 `config.yaml`、`CONFIG_FIELDS`/允许字段和校验、读写页面及迁移规则。新增持久索引应携带 `ownerStoreId` 并实现损坏时保留原文件的行为。专项覆盖：`tests/yaml-configuration.test.mjs`、`tests/storage-v2.test.mjs`、`tests/workspace-root.test.mjs`、`tests/role-memory-production.test.mjs`。
