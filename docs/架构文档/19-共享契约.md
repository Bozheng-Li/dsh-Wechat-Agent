# 共享契约

[返回总架构](01-总架构.md)

## 设计目标

`shared/` 保存前端、后端和 Worker 均可复用的**无实例契约**与纯函数，避免管理页面自行猜测服务端字段、让子进程越权依赖业务组件。它可导入纯提示常量/人设格式化数据，不应包含账号凭据、文件读写、运行时服务或长连接对象。

## 文件与职责

| 范围 | 代表文件 | 主要内容 |
| --- | --- | --- |
| 通用 | `contracts.mjs`、`text.mjs` | `CHANNEL`、`ChannelError`、账号/模型/会话设置校验、可公开错误与基础文本规则 |
| 记忆 | `memory-policy.mjs`、`image-memory.mjs`、`role-card.mjs`、`message-references.mjs` | 保留期、图像集合、角色卡字段、引用消息结构 |
| 工作 | `work-artifacts.mjs`、`work-image-request.mjs`、`image-generation.mjs` | 文件成果元数据、生图请求与提供方设置 |
| 朋友圈 | `moments*.mjs` | 动态作者主体、可见范围、发布/互动/点赞/素材等输入校验和投影 |
| 任务 | `task-history.mjs` | 定时任务及执行记录展示结构 |

`contracts.mjs` 的 `eligible` 只按设置做基础判断；带会话授权语义的调用点改用 `shared/authorization.mjs` 的 `conversationEligible`（总开关 + 对象授权），`validateConversationSettings` 约束模式和配置，`ChannelError` 给出机器可识别错误码与安全公开消息。共享文件只表达数据形状，不决定“这个微信用户是否允许操作”：最终授权由后端 RPC、会话服务或业务模块依真实状态判断。

`shared/authorization.mjs` 区分两层：`personAuthorized` 接受显式私聊授权或已授权群聊的成员；私聊会话的 `conversationAuthorized` 直接跟随 `personAuthorized`，所以已授权群聊的成员私聊不必再单独授权，`conversationEligible` 在这个判断上再叠加自动回复总开关。成员名单由 `modules/authorization/members.mjs` 后台刷新并写入 `channel.json` 的 `groupMemberIndex`，判断本身保持同步、不等待协议；每条记录同时保存当前成员 `ids` 和确认过的 `seen`，`groupMemberExclusions` 记录管理员明确取消过的个人，优先于群成员身份。启动清理用 `conversationScopeAuthorized`：名单由协议派生、可能不完整，成员退群只收回访问并保留已有资料（`seen` 仍覆盖），取消整个群授权或明确排除某人时才按授权清理。

## 扩展约定

新增跨端状态字段先明确默认值、非法输入和兼容行为；保持返回值结构可序列化，禁止把 Node 实例、Buffer 或私钥混入浏览器状态。新增跨端验证需同时覆盖有效、异常、旧配置迁移和账号隔离。结构测试 `npm run test:structure` 检查依赖边界；功能覆盖参考 `tests/message-references.test.mjs`、`tests/image-generation-providers.test.mjs`、`tests/task-history.test.mjs` 与对应朋友圈测试。
