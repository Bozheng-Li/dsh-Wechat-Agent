# 前端工作台

[返回总架构](01-总架构.md)

## 安装与入口

`frontend/index.jsx` 导出浏览器插件的 `inject`、`apply` 与 `WechatPanel`；`frontend/entry.jsx` 向 DSH 的 `main` 槽注册面板、向侧边栏注册“微信 Agent”入口。构建后由 DSH 加载 `lib/client.js`，页面并非独立 Vite 站点。`panel.jsx` 渲染导航和整体布局，`page-content.jsx` 按页面 ID 选择功能页；`hooks/use-panel.mjs` 维护账号状态、页面切换、草稿、会话列表与 RPC 结果。

## 页面组织

| 目录 | 页面职责 |
| --- | --- |
| `pages/overview`、`conversations` | 连接概览、授权会话和会话级回复模式 |
| `pages/records`、`recovery` | 消息处理历史、引用证据与发送恢复 |
| `pages/memory` | 会话窗口、长期事实、角色卡、图片记忆和维护 |
| `pages/work`、`tasks`、`digests` | 原生工作任务、提醒、群聊简报 |
| `pages/moments`、`media` | 朋友圈、朋友圈素材库、聊天表情与素材 |
| `pages/settings`、`diagnostics` | 模型、搜索、人设、身份、管理员、数据目录、诊断 |

`components/` 放控件、选择器和状态组件；`hooks/use-workbench.mjs` 维护工作台相关操作。`frontend/shared/rpc.mjs` 是唯一页面 RPC 适配；`drafts.mjs` 负责状态→表单→保存 payload 的转换，未保存草稿与服务器当前值分开管理。会话切换时用账号、peerId 等作为组件 key，避免旧账号草稿或请求结果污染新账号。

## 样式和状态反馈

`styles/tokens.mjs` 定义亮暗模式颜色与字体，`foundation.mjs` 负责控件，`layout.mjs` 负责导航，`automation.mjs`、`content.mjs`、`settings.mjs`、`interactions.mjs` 各自管理业务表面；`styles/base.mjs` 汇总样式。页面将处理中、成功、未知、失败等状态同时表达为文字和颜色。响应式导航和减少动态效果偏好在面板层处理。视觉细节另见 [视觉系统](../VISUAL-SYSTEM.md)。

## 新增页面的步骤与验证

新增视图先补页面组件和 `page-content.jsx` 的分发，再补导航/标签、草稿与 RPC 调用；权限错误、异步取消、空列表、加载态及窄屏都需要可见反馈。测试入口 `npm run test:ui`、`npm run test:visual`、`npm run test:workbench-ui`；不要用 UI 状态代替服务端授权检查。
