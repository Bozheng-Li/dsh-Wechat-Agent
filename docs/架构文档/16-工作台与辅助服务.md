# 工作台与辅助服务

[返回总架构](01-总架构.md)

## 聚合协调

`modules/workbench/service.mjs` 的 `AgentWorkbench` 聚合四类 Owner 工作台能力：运行诊断、群聊简报、发送恢复和事实复核。`WORKBENCH_ENDPOINTS` 在 RPC 白名单与 `service.call` 中复用；`workbench/store.mjs` 为独立业务数据提供账号隔离和 revision。这里的“工作台”是管理功能聚合器，不等于 `modules/work/` 的原生 DSH 工作任务。

## 辅助子模块

| 模块 | 文件 | 作用与输入 |
| --- | --- | --- |
| 诊断 | `modules/diagnostics/service.mjs` | 运行指纹、微信/模型/搜索/图片检查；配置变更或超时后标记 stale |
| 简报 | `modules/digests/service.mjs` | 在已授权群聊的指定时间段整理摘要和待办；待办可关联定时提醒 |
| 恢复 | `modules/recovery/service.mjs` | 查找 `unknown`/`partial` 发送记录，准备补发草稿、核对旧回执并由用户明确提交 |
| 清理 | `modules/cleanup/service.mjs` | Owner 预览待清理记录、冻结 ID/revision，再删除可清理展示项 |
| 事实复核 | `workbench/service.mjs` | 对长期事实执行更新、解决与删除，关联记忆模块的来源约束 |

简报、诊断等模型请求只以已校验的会话数据为输入；群聊简报限定授权群与时间窗口，不能混入其他会话。恢复和清理都是高风险操作：恢复不得把未知回执当成未发送；清理只是本地记录管理，不会撤回已发微信内容，也应保留防重所需请求凭据。长操作依赖插件生命周期和调用方取消控制。

## 页面与验证

管理页面分别在 `frontend/pages/diagnostics/`、`digests/`、`recovery/`、`records/`。测试见 `tests/workbench.test.mjs`、`tests/workbench-deletion.test.mjs`、`tests/workbench-store-compatibility.test.mjs`、`tests/owner-cleanup.test.mjs` 与 `npm run test:workbench-ui`。扩展工作台时在 endpoint、存储、界面与权限测试四处同步修改。
