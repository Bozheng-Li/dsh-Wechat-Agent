# 定时任务

[返回总架构](01-总架构.md)

## 核心组件

`modules/tasks/scheduler.mjs` 的 `TaskScheduler` 保存任务和运行历史到工作目录 `storage/tasks/schedules.json`，启动由 `WechatRuntime.activate()` 控制，关闭时等待执行结束。`actions.mjs` 提供 Owner 管理操作；`conversation-tools.mjs` 暴露聊天中按需创建/管理提醒及搜索、素材辅助工具。`shared/task-history.mjs` 提供历史投影。

## 计划类型和执行

| 类型 | 参数 | 下一次计算 |
| --- | --- | --- |
| 一次性 `once` | 将来时刻 `at` | 到时执行一次 |
| 每天 `daily` | 本地 `HH:mm` 和时区（默认 `Asia/Shanghai`） | 在指定时区找下一次日期 |
| 间隔 `interval` | 分钟数 | 从本次基准计算下一次 |

`validateSchedule` 限制时间范围，`scheduleNext` 统一推算。聊天中的简单提醒由 `conversation/reply.mjs` 的快速识别路径直接保存任务；复杂安排通过注册给模型的任务工具处理。执行时由 scheduler 提交到 `channel.submitScheduled`，再复用普通回复路径，记录发送意图、执行结果和微信服务端回执。短时倒计时确认不等待模型生成冗长措辞。

## 群成员与安全边界

群内 @ 对象必须从实时成员列表按 ID 确认，`savedTargets` 限制最多 20 人且拒绝 `@所有人`；发送前 `resolveTargets` 重新核实，真正输出 `at` 段，而不是文字里伪造 @。任务需保持插件在线、当前账号匹配、会话仍授权并允许聊天任务。到期失败/结果未知会在运行历史保留，不假装送达，也不因重启自动补发旧发送。

## 维护与测试

改时间算法须测试跨日、夏令时和重复时刻；改任务发送须覆盖权限撤销、取消、丢失回执和真实 @。参考 `tests/scheduled-features.test.mjs`、`tests/task-mentions.test.mjs`、`tests/task-history.test.mjs`、`tests/agent-task-boundaries.test.mjs`、`scripts/test-scheduler-clock.mjs`。
