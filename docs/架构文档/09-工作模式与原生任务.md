# 工作模式与原生任务

[返回总架构](01-总架构.md)

## 范围与授权

工作模式由会话设置的 `executionMode='work'` 控制，发起者还须满足 `modules/work/policy.mjs` 的实际账号、会话授权和 `workSenderIds`/管理员策略。`modes/service.mjs` 实现 `/mode` 切换并取消旧队列；`commands.mjs` 解析 `/work` 明确指令；自然文字交给 `routing.mjs` 判断是工作、继续任务还是普通聊天。明确权限在创建任务、每次工具执行、文件读取及结果回传前重新检查。

## 任务生命周期

`WorkService`（`service.mjs`）以 `WorkStore`（`store.mjs`）记录任务，队列支持配置并发（默认 2）、每个工作目录同一时刻只执行一个任务，并保存执行中止、错误、工具操作、结果及回传状态。`create` 为新任务分配 ID 与 `workspace/微信agent/work/<id>` 目录；续接可沿用原目录和 DSH session，任务已存在的桌面写入锁冲突须在提交新消息之前解决。

`DshWorkRunner`（`runner.mjs`）直接向原生 DSH Agent 提交原话，保留原生预设、模型、上下文和已有工具，补充 `workModelTools({surface:'native'})` 的微信能力；并行子任务在 `work-sessions.mjs` 创建。工作不会自动注入聊天历史或全套聊天人设，只有必要时用限定的 `wechat_memory` 工具读入请求之前的会话快照。`progress.mjs` 汇报执行进度，`polish.mjs` 独立润色最终文字，保留原文及失败回退。

开工确认通过正常回复路径发送并单独保存微信回执，回复收尾后释放已安排的任务。`WorkProgressReporter` 在任务进入执行状态后每 3 分钟采集有限的原生会话活动和工具状态，由独立、无工具的模型请求生成一两句进度；不读取工具原始输出或思考内容，不追加工作指令。进度发送使用 `workProgress` 标记，不准备成果附件或改变最终回传状态。任务结束或取消时停止计时器并取消未完成进度；迟到模型结果不会阻塞最终回传。进度发送结果不明时停止后续自动进度，保留记录供核对，最终结果仍按独立流程发送。

## 成果与回执

`artifacts.mjs` 校验显式登记或原生工具产出的文件；`image-storage.mjs` 为生图与变更图片创建历史快照；`image-generation.mjs` 管理兼容图像生成 API 的提供方、模型与凭据。工具说明来自当前目录，模型选择接口、模型、尺寸；同请求去重，失败不隐式切换服务。任务最终结果写入工作目录并由 `deliver` 转交会话的定时发送路径，文件字节直接通过微信协议发送。每个文件用哈希、大小、名字、服务端消息 ID 逐项确认，`delivery` 可能是 `sent`、`partial`、`unknown` 或 `suppressed`；结果不明不自动重发，`delivery.mjs` 提供明确的恢复路径。

## 关键文件与测试

`dialogue.mjs` 负责工作对话和任务创建回执；`session-history.mjs` 提供按需历史；`connections.mjs` 封装管理员 SSH/VS Code 访问；`policy.mjs` 控制任务路径与访问边界；`presentation.mjs` 约束对话表现不污染用户成果文件。重点测试 `tests/work-mode.test.mjs`、`tests/work-permissions.test.mjs`、`tests/work-artifacts.test.mjs`、`tests/work-parallel.test.mjs`、`tests/work-image-storage.test.mjs`，原生隔离入口 `npm run test:work-native`。
