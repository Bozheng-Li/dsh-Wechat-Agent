# 素材库与表情

[返回总架构](01-总架构.md)

## 模块边界

`modules/media/library.mjs` 管理账号的微信收藏、聊天表情和自行导入的图片。`sticker-service.mjs` 负责后台同步、聊天收集、情景整理与所有者操作；`sticker-tools.mjs` 提供日常会话的读取和发送工具。此库与朋友圈的 `modules/moments/materials.mjs` 分别保存数据。前端位于 `frontend/pages/media/`，Owner RPC 由 `modules/media/actions.mjs` 接入。

## 资产生命周期

1. 原生协议 `backend/wechat/protocol/stickers.ts` 通过 697 完整分页读取微信收藏，175 按 MD5 发送微信原生表情，696 添加服务器已有表情。收藏操作必须重新读取列表确认，资源 URL 仅保留在微信组件中；不包含删除收藏指令或未知表情上传。
2. `WechatStickerService` 同步收藏元数据并后台下载原图，按消息来源、时间与会话授权收集聊天表情。`wechat-stickers.mjs` 保存稳定的原生资产 ID、实际内容 SHA-256 与来源。账号隔离、内容校验、删除墓碑和事务保存防止混用、错误覆盖或自动复活。旧版三个网上图片分组经事务迁移后清理，自行导入内容保留。
3. `description.mjs` 批量整理已保存表情的实际画面、含义、适用情景和标签。动态图提供首帧缩略图，保留原动画；模型说明按数量和字段校验，异步提交前复核账号、授权、设置和素材版本。后台任务不占用聊天队列，不覆盖人工编辑。
4. `wechat_sticker_read` 按含义或情景检索、读取或随机选取；`wechat_sticker_send` 只接受本轮读到的可用表情。日常会话由模型判断是否合适，不再随机限制工具出现；最小消息间隔防止刷屏，明确要求表情可绕过间隔。一轮最多选择一张。
5. `prepareSendSegment` 提供原生 MD5 与可用时的图片备用内容。原生接口不可用或返回明确拒绝才使用图片替代，GIF/WebP 替代用首帧。回执不完整、取消或超时不触发补发；已确认的文字不重复发送。
6. 所有者仍可导入 ZIP 或单图。`zip.mjs`、`validation.mjs`、`limits.mjs`、`image-format.mjs` 校验路径、格式、真实尺寸、大小与数量；分组和单张启用开关在发送前再次核对。

## 配置与一致性

`config.yaml` 的 `mediaDefaults` / `media` 控制启用、消息间隔、`captureIncoming`、`preferNative` 和 `autoDescribe`；旧 `probability` 字段仅为配置兼容保留。元数据存入 `storage/assets/index.json`，文件按账号分开保存，原生元数据没有假造图片字节。原图缺失可保留原生引用，文件被替换则停止发送该资产。会话沿用 `sending` 到服务端回执的状态机，部分成功不重发未知片段。

## 验证

测试见 `tests/sticker-library.test.mjs`、`tests/sticker-service.test.mjs`、`tests/sticker-tools.test.mjs`、`tests/media-channel-integration.test.mjs` 和 `tests/outbound-media.test.mjs`。`WECHAT_UI_TEST_STICKERS_ONLY=1` 的 Electron 场景验证真实界面与 Owner RPC，使用合成账号和回执。`scripts/probe-wechat-stickers.mjs` 默认只读；原生发送与收藏实测需显式参数。完整包通过 `npm run audit:package` 确认未携带旧图片或私人素材。
