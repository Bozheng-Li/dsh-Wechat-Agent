# 会话接收与回复

[返回总架构](01-总架构.md)

## 模块职责

`modules/conversation/channel.mjs` 是消息路径的协调对象，持有普通回复队列、工作分道、活动任务、暂停令牌、记忆维护及自然陪聊状态。它组装 `ConversationMemory`、`LongTermMemory`、`ImageMemory`、`MediaLibrary`、`WorkService`、`RemoteService`、`MomentsService`、`MomentsAutomation` 和 `AgentWorkbench`；微信 Worker 的 `message` 事件进入 `receiveMessage`。

## 接收准入（`incoming.mjs`）

先验证方向、消息 ID、会话和发送人，再用真实账号、会话及服务端消息 ID 生成去重键。`eligible` 检查授权，会话配置确定默认、昵称、主动参与、自然陪聊或工作模式；过期超过十分钟、账号离线以及暂停中的旧消息只记录跳过，不补发。控制路径优先识别 `/mode`、`/work`、远程只读查询；工作模式的自然文字进入工作意图路由，普通文字按唤醒条件进入聊天队列。

主动参与按固定或随机消息阈值累积，已有排队轮次合并；`natural-chat.mjs` 结合活跃时段、连续接话、人工回复、冷却与发送结果决定是否说话。直接呼叫优先于主动发言，并能取消冗余的环境回复。入队时保留接收时的记忆快照，避免模型排队期间读入之后的消息。

## 执行与发送（`reply.mjs`）

`processReply` 逐项复核账号、授权、在线状态和配置；按任务类型处理模式控制、远程查询、工作命令、定时消息、直接提醒或普通对话。普通对话先处理记忆和引用，按需下载/理解图片；组合记忆上下文、角色信息、工具列表后调用 `DshAgentRunner.run`。可用的工具包括提醒、素材、记忆、朋友圈、图片与联网搜索；工具执行前提示由 `tool-notices.mjs` 控制。

模型返回后，再检查被引用图片、当前人设与会话授权，确定文字、表情、文件和群内真实 @ 目标。**先写入** `state='sending'` 和 `sendAttempted=true`，再调用微信 `transport.send`。回执必须含 `delivery='server-ack'` 和有效的服务端消息 ID；工作成果还逐文件核验。成功记录 `sent` 并保存 Agent session；部分确认记 `partial`，发送后结果不明记 `unknown`，不会自动重发。

## 并发、取消和记忆维护

普通回复由 `drain()` 串行处理，工作回复按会话 `contextKey` 分道；队列设有容量限制，工作任务本身由 `WorkService` 独立调度。`pause`/`cancel`/`whenIdle` 为切换配置、断网、退出提供停止屏障。`memory-maintenance.mjs` 在空闲/有压力时进行压缩，直接请求优先；失败保留原文并等待重试。
