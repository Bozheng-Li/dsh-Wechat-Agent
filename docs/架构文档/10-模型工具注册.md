# 模型工具注册

[返回总架构](01-总架构.md)

## 统一入口

`modules/tools/index.mjs` 的 `workModelTools({surface,...context})` 汇集原生工作工具、任务会话管理、朋友圈、图片与记忆工具；`registry.mjs` 的 `modelToolList`/`registerModelTools` 将定义交给 DSH Tool service，维护本轮的可见工具和执行封装。同名工具在一个执行上下文中只注册一次。聊天工具由 `modules/conversation/reply.mjs` 按实际授权单轮组装，再交给 `DshAgentRunner`；工作工具由 `DshWorkRunner` 传入经过校验的执行上下文。

| Surface | 用途 | 典型能力 |
| --- | --- | --- |
| 聊天 | 普通微信回复，按会话和发起人授权 | `wechat_memory`、看图、提醒、素材、朋友圈、联网搜索 |
| `dialogue` | 保留的工作对话兼容入口 | 查询任务、启动/继续/并行/取消 |
| `task` | 保留的结构化工作兼容入口 | 文件/命令/生成图等执行工具 |
| `native` | 原生 DSH 工作会话 | 工作执行工具 + 会话管理 + 可授权的朋友圈/记忆 |

## 定义与绑定

`work-execution.mjs` 定义文件列读写、命令、SSH/VS Code、生成图片和成果登记；`work-sessions.mjs` 定义任务列表、历史、开始、继续、取消及并行；`moments*.mjs` 各自定义朋友圈读取、配图、点赞、评论互动、发布和素材。`progressive.mjs` 为渐进式提示策略选择初始工具及延迟组；禁用功能不会凭提示词再次获得工具权限。`registerModelTools` 接收每轮 `assertAllowed`，工具执行前复核授权，使用工具时还可调用 `onBeforeTool`。

工具结果不是可信权限凭据；实际读写始终落到业务模块（`WorkService`、`MomentsService`、`TaskScheduler` 等）做第二次校验。`conversation/tool-notices.mjs` 把工具名映射成执行前可见的微信进度提示，发送也走相同回执边界。

## 扩展方式

新能力应先定义输入 schema、返回格式、权限前提与失败语义，在对应工具文件中加入定义，然后将其纳入正确 surface 的列表；若需要提示词，加入 `prompts/` 并同步发布资源白名单。不要仅通过关键词在消息入口新增工具执行捷径，也不要将原生桌面工具不加约束地挂到聊天会话。

## 验证

`tests/work-tools.test.mjs`、`tests/moments-tools.test.mjs`、`tests/progressive-tools.test.mjs`、`tests/tool-notices.test.mjs` 与 `npm run test:work-tools-native`。修改工具 schema/授权后还应覆盖取消、账号切换与错误结果。
