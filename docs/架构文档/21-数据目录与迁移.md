# 数据目录与迁移

[返回总架构](01-总架构.md)

## 包目录与工作目录

插件包目录由 `backend/platform/resources.mjs::resourcePath()` 定位，包含默认 `config.yaml`、`lib/`、`prompts/`、`runtime/` 和素材；用户工作目录默认 `~/.dsh/wechat-agent`，也可通过 UI 指向新的全局目录。实际目录可以与 bootstrap 分离：bootstrap 只保留定位/互斥入口，所有运行服务均以实际 root 构造。包目录不可作为账号数据备份来源，也不要通过相对进程 cwd 定位资源。

## 运行数据布局（示意）

```text
<实际工作目录>/
├─ config.yaml                         业务设置，账号授权、人设、模型与路径
├─ prompts/                           用户自定义身份和人设正文（不是包内模板）
├─ storage/
│  ├─ state/channel.json               运行索引、已见消息与会话入口
│  ├─ conversations/账号-*/.../conversation.json
│  ├─ memory/                           会话窗口、长期 Markdown、图片、角色卡
│  ├─ tasks/schedules.json              提醒及运行历史
│  ├─ work/                             工作任务状态与图像归档
│  ├─ moments/                          朋友圈回复、发布、点赞、互动和素材
│  ├─ media/                            素材库数据
│  ├─ private/                          登录会话等私有状态
│  ├─ cache/、tmp/、logs/              协议缓存、临时文件与日志
│  └─ backups/                          迁移保护副本
└─ workspace/                          DSH Agent 的可工作目录
```

各功能还可能在 `storage/` 下建立专用子目录，磁盘实物以模块的 `file()`/`paths()` 方法为准；上图不代表每个新实例都会预先创建全部目录。`storage/state/config-transaction.json` 是配置提交中断时的 journal，重启先恢复。

## 迁移协议

`backend/storage/workspace.mjs` 的 `readWorkspaceLocation` 读取当前数据根；`migrateWorkspaceRoot` 对目标路径、符号链接、归属与写入能力做检查，迁移期间保留回滚信息。`backend/app/plugin.mjs::relocateWorkspace` 停旧 runtime → 复制/迁移 → 在目标打开新的完整 runtime → 提交定位指针 → 将 RPC 服务引用换到新实例 → 激活，失败时回滚并尝试恢复原实例。旧目录继续保留；不要手动移动仍在线的账号目录或删除 `ownerStoreId`。

旧版单文件会话状态通过 `backend/storage/initialize.mjs` 备份后拆成每会话快照；旧配置迁到 YAML 前保存 `channel.before-yaml-<摘要>.backup.json`。外部编辑 YAML/人设后重新启用插件；配置签名冲突会拒绝保存，防止页面覆盖用户修改。无效源文件应保留原状并给出明确错误，而不是初始化新空账号。

## 验证与恢复

目录相关测试 `tests/workspace-root.test.mjs`、`tests/runtime-workspace.test.mjs`、`tests/storage-v2.test.mjs`、`tests/yaml-configuration.test.mjs`。故障排查先确认实际 root、`ownerStoreId`、备份与 journal，再区分“配置写入失败”“目录迁移未提交”和“Worker 未连接”；不要把发送中断记录当作可自动重发任务。
