# DSH 验收加载冲突与恢复 · 2026-11-07

04:42–04:43 UTC，真实模型验收期间，DSH 发生 `clientModules` 服务启动失败，桌面显示 unavailable。诊断记录明确报告：正式 `dsh-plugin-wechat-agent` 与仓库内两个临时 `core-model-audit.cjs` Loader 来源被解析为同一个客户端包。这次故障由验收加载方式引起。

临时脚本原先位于仓库子目录，却没有自己的 `package.json`，宿主向上查找包边界时读到正式微信插件的客户端声明。多个加载来源在客户端模块重新组合或宿主重启时触发冲突；此前单纯模型任务成功不能证明客户端重新组合安全。

恢复操作保留正式插件、账号与自动回复配置，只清理本轮临时测试项。确认当前 profile 中临时 ID 与来源路径均为零后，保存干净 profile 备份，正常关闭错误窗口并重新打开 DSH。没有关闭其他应用，也没有群发通知。

恢复后使用修复后的服务端只读检查核对：`online=true`、`good=true`、`runtimeReady=true`、自动回复开启；账号 hash、配置 hash、凭据配置状态前后一致。检查不调用模型或微信发送，结束后移除自己的临时项，原 profile 恢复。

验收加载器现在在每个临时目录创建独立、私有、CommonJS 包，名字为该次审计的唯一 ID，且没有 `dsh.client` 入口。依赖的源代码与测试构建仍按 SHA-256 冻结；包边界阻止客户端注册器继续向上读取正式插件清单。后续真实验收应串行执行并检查客户端组合与清理结果，避免临时加载变更重叠。

本地证据位于 `storage/logs/dsh-recovery-20261107/`，包含 profile 备份、只读健康结果和加载／清理结果，不随发布包分发。

后续串行真实模型检查和本地修复包加载完成：测试插件均具有独立包边界，原 profile 恢复。新包 485 个文件核验一致，实际页面与微信连接正常；完整记录见 `MEMORY-RELIABILITY-2026-11-07.md`。
