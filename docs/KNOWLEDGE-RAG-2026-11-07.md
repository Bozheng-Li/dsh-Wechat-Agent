# 按需知识库 · 本地审阅

知识库使用本地全文索引，不使用 embedding、向量服务、模型重排或自动查询改写。查询总开关默认关闭；开启后，也只有当前消息明确要求查询知识库时才运行这条链路。源码仍为未发布修改，未提交 GitHub、未发布 npm、未覆盖正式实例。

## 使用方式

1. 在“资料与记忆 → 知识库”新建资料库，导入 Markdown、TXT、PDF 或 DOCX。原文独立保存；上传不会调用模型，也不会立即建立全文索引。
2. 开启页面顶部的“知识库查询总开关”。管理员可用“检索原文”测试匹配；它只读本地索引，不调用回答模型。“依据资料回答”在命中原文后调用一次所选模型。
3. 如需在微信使用，编辑单个知识库，勾选“启用会话知识检索”并选择已授权的会话。这层范围控制与账号总开关同时生效。
4. 在微信发送 `/kb 退款期限`，或直接呼叫助手后说“查知识库：退款期限”。群里的 `/kb` 本身是明确命令；自然语言仍遵循群聊的 @、昵称唤醒等规则。关闭总开关时会直接说明，没有模型调用。

普通聊天、主动参与、定时任务不会注册知识库工具或自动查询知识库。引用、翻译、否定要求、历史内容、图片描述及文档中的指令不构成新的查询授权。对不明确的表达保守处理；需要可靠指定时使用 `/kb 问题`。

总开关关闭不影响导入、阅读原文、管理会话范围和手动重建本地索引。开启与关闭均按账号保存；旧资料没有这项设置时保持关闭，不丢弃已有文档。

## 查询与费用边界

```text
当前明确请求
  → 核对账号、总开关与会话范围
  → 原始问题的本地 FTS5 检索一次
  → 未命中：直接说明，结束
  → 命中：最多 4 段、每段 750 字、合计 3000 字
  → 将问题与这些片段交给回答模型一次
  → 重新核对资料修订号及授权，返回答案与来源
```

问题最多 200 字。检索不访问网络；首次查询需要建立本地索引，耗费本机 CPU、磁盘和少量等待时间，没有嵌入费用。命中问答按当前聊天模型的实际价格计费，页面显示检索次数、片段数、文字量和回答模型调用次数，而非估算账单或虚构 token 数。

没有命中不会调用回答模型，不自动换词重查，也不自动转 Tavily 或 DeepSeek 搜索。命中问答的模型会话关闭全部工具，不继承宿主文件、网页或其他 Agent 工具；不再额外进行回复润色。原文是引用资料，不是模型指令或工具授权。

上述次数描述本次知识库链路。独立启用的长期记忆整理等后台功能仍遵循各自设置，不会因此获得知识库查询权限，其用量也不算作知识库的回答调用。

## 索引设计

- 原文继续保存在 `storage/knowledge/<账号哈希>.json`。派生索引位于 `storage/knowledge-index/<账号哈希>.sqlite`，索引状态保存在相邻元数据文件。
- 通过 `node:sqlite` 延迟加载 SQLite FTS5。Node 与 DSH Electron 均使用实际运行时验证；无需额外安装向量数据库或嵌入模型。
- 中文采用相邻双字词，英文与数字标识符采用词项；查询去掉有限的常见虚词，最多 24 个词项。FTS5 使用 BM25 排序，标题和段落标签权重高于正文。SQL 使用参数绑定，查询中的引号、OR、NEAR 和通配符不会作为用户提供的 FTS 表达式执行。
- 先按账号与会话允许的库过滤，再取有序候选片段。返回原文附近的有限上下文及文件名、章节或页码、段落号；不向模型发送整库。
- 截取片段使用 FTS 标记的实际命中词，再把归一化位置映射回原文；`refunds` 可以定位 `refund`，`AB-123` 可以定位全角 `ＡＢ－１２３`，`cafe` 可以定位 `Café`。输出保留原始字形，分段不拆开表情等 Unicode 字符。
- 索引归属绑定账号、插件存储标识及原文指纹。首次查询按需建立，同一账号的并发构建排队并复用最新有效索引；使用事务及临时文件完成后替换。
- 原文变化或关闭查询会中止正在进行的知识库操作。生成完成后和微信发送前再次检查修订号、连接与会话授权；旧结果不能越过这道边界。无效、过期的设置不会取消有效查询，普通聊天也不因知识库变更而中断。
- 索引损坏或过期时从现有原文重建一次。原文损坏、存储归属不符或目录重定向时明确报错，不用空白文件覆盖资料。已跨越发送边界的真实微信回执依旧按原规则记录。
- 高频读取复用一个不可变快照，每次仍核对文件身份、大小、纳秒级写入/变更时间及存储归属；文件外部改动即使未增加修订号，也使旧答案失效。资料编辑使用独立对象，不会改写读缓存。派生索引在独立临时文件中构建，避免每次派生表操作同步刷新磁盘和执行全库优化；原文文件的保存规则不变。

这是关键词 RAG。使用原文中的产品名、术语、编号和短语效果更稳定；不承诺无关键词重合时的语义召回，也不为提高召回额外调用模型。命中代表有相关词项，不等于模型已证明答案正确；页面同时给出原文供核对。扫描版 PDF 仍需先 OCR。

## 验证与审阅

定向回归覆盖默认关闭、旧资料兼容、中文与英文召回、会话与账号隔离、查询预算、损坏索引重建、并发与取消、拒绝存储重定向、引用和陈述不授权、定时与主动参与无工具、模型参数不能扩大查询，以及关闭开关、撤权、删除、切换账号和取消后的迟到答案。新增回归还验证命中片段、Unicode 边界、可解析但结构损坏的记录、同长度且恢复原修改时间的外部改动；错误时原文保留。

DSH 原生验证确认：知识库答案保留会话人设、全局身份、账号补充要求与说话人，只有一次模型请求，且全部工具关闭；未命中没有模型请求。界面验收覆盖总开关、原文阅读、首次索引、重建、用量、导入和删除，明暗主题与 320/430/768 像素布局均验证。查询中可直接关闭开关，旧模型响应迟到时不会清空新请求状态或展示旧答案。验证使用隔离合成账号、模型与微信回执，没有真实微信测试消息或群通知。

### 本地容量实测

在 Windows x64、Node 24.16.0 上，用 150 份合成文档、共 800 万 UTF-16 字符和 8100 个分段实测。使用本地合成标识符查询，没有模型或网络调用。命中与范围隔离、输出限额、取消后原文完整和临时索引清理同时验证；这些数值代表本机样本，不能当作所有电脑或所有文档的性能保证。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首次查询（含建索引） | 4162 ms | 1959 ms |
| 12 次重复查询中位数 | 492 ms | 5.34 ms |
| 重复查询 p95 | 550 ms | 6.81 ms |
| 最长事件循环延迟 | 2003 ms | 185 ms |
| 25 ms 取消定时器实际触发 | 562 ms | 30 ms |
| 收到取消后的结束时间 | 2.35 ms | 1.90 ms |
| 进程峰值 RSS（含测试数据） | 408 MiB | 216 MiB |

优化后的索引为 74,903,552 字节，原文 JSON 为 21,541,208 字节；不同内容的体积会变化。复现命令：`node scripts/benchmark-knowledge.mjs`，报告在 `storage/logs/knowledge-capacity-before.json` 与 `storage/logs/knowledge-capacity-after.json`。基准只用隔离临时目录，不读取真实账号或生产资料。

最终回归数量、预览入口及本地包校验见[工作台审阅说明](WORKBENCH-REVIEW-2026-11-06.md)。
