# 工作台与知识库 · 本地审阅

本轮落实运行检查、发送恢复、记忆维护、群聊简报四项功能，并以知识库替换论文阅读建议。新增内容仅供本地审阅，尚未提交 Git、推送 GitHub、发布 npm 或替换正在运行的插件。

升级前的对照基线已在 GitHub：[`8bbb65d87cd7a1705e786dbb85e508a67349bedd`](https://github.com/Bozheng-Li/dsh-Wechat-Agent/commit/8bbb65d87cd7a1705e786dbb85e508a67349bedd)。源码保留 `0.2.0-preview.6` 版本号，应用顶部单独显示“本地审阅 · 未发布”，避免将源码更新冒充正式发布。

## 菜单与操作

| 菜单组 | 入口 | 本轮行为 |
| --- | --- | --- |
| 会话工作 | 概览、会话、记录 | 原有入口保留 |
| 会话工作 | 发送恢复 | 保留原回复；准备原内容、仅文字、仅图片或重新生成的草稿，核对接收会话后手动发送 |
| 会话工作 | 群聊简报 | 按授权群和时间段生成结论、未解决问题、待办，并保留原始消息依据 |
| 会话工作 | 定时任务 | 简报待办确认后可转为一次性提醒；在定时页核对或取消 |
| 资料与记忆 | 记忆库、记忆维护 | 原记忆编辑与窗口设置保留；新增冲突确认、有效期、原文依据和历史分类 |
| 资料与记忆 | 知识库、素材 | 文档资料与图片素材分别管理；知识库按用途建库，再选择允许检索的会话 |
| 运行与设置 | 运行检查、设置 | 真实检查连接、模型、搜索、图片条件和知识索引，保留结果时间及可理解的失败原因 |

卡片采用现有冷白、石墨主题及蓝色点缀，提供明确标题、状态、数据与操作层次。窄窗口下菜单可以滚动，内容转为单栏；减少动态效果设置继续生效。

### 运行检查

- 手动开始后，向当前模型请求最小 `OK` 回复；搜索仅测试当前启用的服务，关闭时明确显示“已关闭”。检查可能产生已配置服务的用量。
- 图片项只检查本机组件及登录参数，不发送微信测试图片，不表示实际投递成功。
- 每项记录检查时间；超过五分钟、连接状态或实际所选模型等发生变化时，提示重新检查。检查期间配置变化则拒绝保存混合结果。

### 发送恢复

- 准备草稿不会发送消息；再次勾选确认并提交后才进入同一可靠发送队列。
- 微信已确认的文字或图片不能重复发送。结果不明时，必须先核对微信并确认未收到；旧记录若无法把部分回执对应到具体内容，禁止直接重发。
- 每次恢复单独保存记录，原始失败记录保留。重复提交同一草稿不会重复投递；取消后迟到的真实回执仍保留。
- 队列明确未接收时恢复可重试草稿；不将发送结果不明的尝试自动复位或重发。
- 草稿十五分钟后失效。送出前重新核对账号、授权、原记录状态及素材可用性。

### 记忆维护

- 临时事实可设到期时间；到期后退出模型有效记忆，原文保留供查阅。
- 模型提取到更正时保存为候选，旧事实暂停作为确定信息使用。管理员选择“采用新事实”或“保留旧事实”后才恢复确定状态，并保留更正历史。
- 有效期修改与冲突确认都核对文件修订号，旧页面不能覆盖新内容。每条事实可查看保存的来源引用。

### 群聊简报与待办

- 每次选取不超过七天的时间段，从本机保留的最多一千条会话消息中取最多三百条、六万字。页面显示实际纳入范围和截断情况，不将本机记录称为微信完整历史。
- 所有结论、问题和待办都必须引用已有消息编号；格式或引用不合格时不保存。
- 待办先作为草稿，确认后才可设置发送到原群的提醒。生成简报不群发、不自动安排提醒。
- 提醒已落盘、简报引用保存失败后，重试会找回同一提醒，不会因修改表单时间而重复创建。卡片显示实际保存时间，并同步已取消或已完成的任务状态；去重跨重启保留，且按账号与会话隔离。
- 删除简报会同时删除其中的待办；已创建的定时提醒独立保留，页面明确提示到定时页管理。

### 知识库

1. 新建知识库，填写名称和用途；查询总开关默认关闭，可先整理和阅读原文。
2. 导入 UTF-8 Markdown/TXT、可提取文字的 PDF 或 DOCX。每份最多 12 MiB、五十万字；PDF 最多二百五十页。扫描件需先 OCR，加密 PDF 需先解密。
3. 开启总开关，用“检索原文”核对命中段落，再用“依据资料回答”查看带来源的回答。首次明确查询时建立本地 SQLite FTS5 索引；检索不调用模型，命中后只把最多 4 段、3000 字交给回答模型一次。
4. 如需在微信查询，在单库设置中启用会话检索并选择已授权的私聊或群聊。发送 `/kb 问题` 或明确要求“查知识库：问题”才检索；普通聊天、主动参与、定时任务都不自动查询。
5. 可预览和删除文档、停用知识库或调整范围。先校验修改有效性，无效或过期的保存不误取消现有回复；撤销范围只取消相关知识库旧查询，普通聊天继续。资料变化期间生成的答案丢弃，微信发送前再次核对修订号。

每个账号最多三十个知识库、一百五十份文档、八百万字；同一知识库内相同文件不重复导入。当前检索使用中文双字词、英文词项和 BM25 排序，无嵌入模型；未命中不调用回答模型、不自动重查或转外部搜索，可另发具体关键词。完整设计与 Harness 参考见[按需知识库说明](KNOWLEDGE-RAG-2026-11-07.md)。

## 深入排查修复记录

| 触发条件 | 修复与验证 |
| --- | --- |
| 删除文档或整个库后尚未再次查询 | 删除原文前先清理旧 SQLite 派生副本；清理失败保留原文与授权。文档、整库及失败回归通过 |
| 昵称后直接要求查知识库 | 剥离已配置昵称后进入固定检索路由；否定、引用与相近英文名字仍不授权。昵称路由与反例回归通过 |
| 微信知识库问答进入内部工作台模式 | 使用面向会话的知识问答模式，保留人设与全局要求；原生 DSH 验证仍只有一次模型调用、零工具 |
| 英文复数、全角编号或重音词在片段尾部命中 | 按 FTS 实际命中定位并映射回原始字形；三个原文定位案例及 Unicode 分段回归通过 |
| 讨论“查知识库”这个词，或读取结构损坏的文档 | 前者不检索；后者明确报错且不覆盖原文件。反例与原文件字节保持回归通过 |
| 查询中保存相同设置、关闭开关或收到迟到响应 | 相同设置不取消；关闭可中止旧请求，迟到结果不能覆盖新操作。后台回归和实际界面交互通过 |
| 文件被外部改动，但修订号或修改时间被保留 | 每次核对文件快照身份，旧答案在生成后与发送前均失效。等长改动、恢复 mtime 和迟到答案回归通过 |
| 恢复队列明确已满，或提醒已保存但简报引用写入失败 | 前者恢复可重试草稿，后者找回原提醒及其真实时间；不自动重发不明结果。队列、重启、账号/会话隔离及取消状态回归通过 |
| 大知识库反复读入整库并同步优化派生索引 | 复用不可变读取快照，保留逐次归属与文件变化检查，减少建索引期间阻塞。800 万字容量实测与取消验证通过 |

## 预览与验证

在插件仓库运行 `npm run preview:workbench`，打开终端返回的 `http://127.0.0.1:<端口>`。浏览器中的数据来自独立临时目录，顶部标明“合成会话 / 不连接真实微信与模型”。可实际操作菜单、导入自己的测试文档、确认草稿和检索；预览问答与发送回执由合成适配器返回，不会联系真实微信或模型服务。

界面自动验收：`npm run test:workbench-ui -- <Electron 可执行文件绝对路径>`。截图与机器报告位于 `storage/logs/workbench-preview/`。

本轮验证使用隔离数据、合成模型与模拟微信回执。真实 PDF/DOCX 解析和 DSH 宿主工具接入均执行实际代码。没有发送真实微信消息、图片或群通知，也没有访问或改写生产账号的私有数据。
